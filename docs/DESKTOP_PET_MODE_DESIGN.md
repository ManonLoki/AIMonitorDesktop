# AIMonitorDesktop 桌宠模式设计

## 1. 文档状态

- 状态：已实现，与当前实现同步
- 版本基线：`2.0.3`
- 最近核对日期：2026-07-28
- 适用平台：Windows、macOS
- 相关基线：`PRODUCT_REQUIREMENTS.md`、`TECH_STACK.md`
- 实现来源：`src/`、`src-tauri/src/` 与 `src-tauri/tauri.conf.json`

本文记录 2.0.3 桌宠模式的当前产品行为、窗口架构、持久化字段与验收边界。
实现变更如影响本文任一条目，必须在同一提交中更新本文及项目级文档。

## 2. 目标

在不改变现有局域网监控协议、25 个槽位和主监控能力的前提下，增加一种适合长期停留在桌面的轻量展示模式。

桌宠模式使用各监控槽位传入的角色图片，不使用一只固定角色代替所有监控对象。

## 3. 已确认的核心决策

1. 主界面与桌宠是互斥的两种显示模式，任意时刻只显示一个。
2. 两种模式使用各自独立的原生窗口和 React UI，但共享同一个 Rust `Runtime`、监控槽位和后台服务。
3. 应用持久化当前模式。开机自启或普通启动时，直接恢复当前模式及其历史窗口状态，不先闪现另一模式。
4. 桌宠支持 1×1、1×2、2×1、1×3、3×1 和 2×2 布局，默认使用 2×2。
5. 六种布局每页分别显示 1、2、2、3、3、4 个槽位并按页浏览。
6. 分页到达首尾后循环。
7. 双击桌宠的非控制区域返回主界面。
8. 桌宠默认始终置顶；首版不支持鼠标穿透。
9. 右键桌宠打开独立设置窗口；设置窗口每次都在桌宠当前所在显示器的工作区居中。

## 4. 产品模型

### 4.1 运行模式

定义持久化枚举：

```text
activeMode: main | pet
```

- `main`：显示现有监控与设置主窗口。
- `pet`：显示透明、无边框的桌宠窗口。
- 切换模式不会停止 HTTP、UDP、mDNS、心跳清理或其他后台能力。
- 隐藏到托盘不会改变 `activeMode`。
- 只有成功完成模式切换后才更新 `activeMode`。

“互斥”是用户可见层面的约束。实现可以提前创建隐藏窗口，但不得让两个窗口同时停留在桌面上。

### 4.2 槽位范围

后端继续维护固定 25 个槽位，现有 HTTP API 和槽位编号保持不变。

桌宠可浏览的槽位数量由主监控配置决定：

```text
visibleSlotCount = rows × columns
```

例如：

| 主监控配置 | 桌宠可浏览槽位 |
| --- | --- |
| 1×1 | 1 |
| 2×2 | 1～4 |
| 3×3 | 1～9 |
| 5×5 | 1～25 |

桌宠布局仅决定一页容量，不修改 `rows`、`columns` 或局域网 API 返回值。

## 5. 窗口架构

### 5.1 主窗口

- 窗口标签：`main`
- 保留普通窗口装饰、最小尺寸、监控页和设置页。
- 没有历史记录时按现有产品要求最大化显示。
- 有历史记录时恢复正常窗口几何和最大化状态。
- 关闭按钮继续执行“隐藏到托盘”，不退出应用。

### 5.2 桌宠窗口

- 窗口标签：`pet`
- 透明背景、无系统标题栏、默认始终置顶。
- 不最大化，不套用主窗口的最小尺寸约束。
- 默认不单独出现在任务栏或 Dock；应用仍可通过托盘访问。
- 右键桌宠打开独立设置窗口，提供隐藏、返回主界面、布局、尺寸、置顶和锁定操作。
- 关闭/隐藏桌宠不退出后台服务，也不改变当前模式。

### 5.3 桌宠设置窗口

- 窗口标签：`pet-settings`
- 独立原生窗口、固定尺寸、不可调整大小、始终置顶且不在任务栏或 Dock 单独显示。
- 每次显示前读取 `pet` 的当前显示器，以该显示器工作区为边界居中放置。
- 不使用设置窗口上次所在显示器或全局主显示器决定弹出位置。
- 关闭设置窗口只隐藏设置窗口；切换到主界面时同步隐藏设置窗口。
- 设置窗口不引入独立业务状态，所有控件仍调用 Rust 命令并订阅 `window-state-changed`。

### 5.4 前端组织

三个窗口使用独立的 UI 组合根：

```text
main         -> MonitorApp
pet          -> PetApp
pet-settings -> PetSettingsApp
```

三个组合根按需复用：

- `useMonitorState`
- `useWindowState`
- `MonitorState` / `MonitorTile` 类型
- `WindowState` / `PetWindowPreferences` 类型
- 本机图片 URL 构造规则
- Tauri `invoke`、`monitor-state-changed` 和 `window-state-changed` 事件通路

不为桌宠引入第二套服务端状态管理，也不通过本机 HTTP 完成前后端状态通信。

### 5.5 互斥切换流程

从主界面切换到桌宠：

1. 保存主窗口的正常几何和最大化状态。
2. 创建或取得隐藏的桌宠窗口。
3. 按桌宠当前布局恢复对应几何；不可恢复时使用默认位置。
4. 隐藏主窗口。
5. 显示并聚焦桌宠窗口。
6. 持久化 `activeMode = pet`。

从桌宠返回主界面执行对称流程。

如果目标窗口创建、恢复或显示失败，应重新显示来源窗口，并保持原 `activeMode`，避免两个窗口都不可见。

## 6. 启动与托盘行为

### 6.1 启动流程

初始原生窗口必须保持隐藏，直到偏好加载完成：

1. 加载并迁移偏好数据。
2. 启动共享后台服务。
3. 读取 `activeMode`。
4. 恢复目标窗口的历史状态。
5. 只显示目标窗口。

启动时不得先显示主窗口再切换到桌宠，以免开机自启时出现闪窗。

### 6.2 托盘菜单

托盘菜单按当前模式隐藏无效操作，固定结构如下：

| 看板模式 | 桌宠模式 |
| --- | --- |
| 桌宠模式 | 看板模式 |
| 显示看板 | 锁定桌宠 |
| 开机自启 | 开机自启 |
| 退出 | 退出 |

- “显示看板”只恢复被隐藏的主窗口，不改变 `activeMode`。
- “桌宠模式”与“看板模式”执行互斥模式切换。
- “锁定桌宠”只在桌宠模式显示，并与设置窗口中的锁定状态同步。
- 不在看板模式保留灰色的“锁定桌宠”，也不在桌宠模式显示“显示桌宠”。

## 7. 桌宠布局与分页

### 7.1 布局

```text
PetLayout = single | row | column | row3 | column3 | grid
single capacity = 1
row    capacity = 2
column capacity = 2
row3   capacity = 3
column3 capacity = 3
grid   capacity = 4
```

- 默认布局：`grid`。
- `single` 使用 1×1。
- `row` 使用 1×2，`column` 使用 2×1。
- `row3` 使用 1×3，`column3` 使用 3×1。
- `grid` 使用固定 2×2；最后一页不足四个槽位时保留空位，不重新排版。
- 空槽位平时透明，悬停时显示淡化的“等待数据”。
- 整页都没有角色图片时，非悬停状态保留淡轮廓，避免透明窗口完全不可见。
- 不压缩或重排空槽位，保证角色位置稳定。

### 7.2 分页计算

内部持久化当前关注槽位，而不是只保存页码：

```text
focusedSlot: 0-based slot index
capacity: 1, 2, 3 or 4
pageIndex = floor(focusedSlot / capacity)
pageCount = ceil(visibleSlotCount / capacity)
pageStart = pageIndex × capacity
```

这样切换布局时可以保持用户正在关注的对象：

- 2×2 正在展示槽位 5～8，切换到 1×1 后先展示槽位 5。
- 再切回 2×2 时恢复槽位 5～8。

当 `rows × columns` 减少导致 `focusedSlot` 越界时，将其收敛到最后一个有效槽位；增加时保持原关注槽位。

### 7.3 翻页行为

- 悬停窗口时显示上一页、下一页按钮和紧凑页码。
- 普通鼠标滚轮翻页。
- 第一页向前翻跳到最后一页。
- 最后一页向后翻跳到第一页。
- 除下述首次有图定位外，不因槽位更新自动翻页。
- 窗口挂载后首次观察到有效图片时，如果当前页没有图片，则自动定位到首个有图
  槽位所在页；该初始定位每次窗口挂载最多执行一次。
- 完成首次有图定位后，后续槽位更新不再自动翻页。
- 滚轮需要节流，避免一次滚动跨越多页。
- 窗口获得键盘焦点后，左右方向键可循环翻页。

## 8. 桌宠内容与视觉

### 8.1 角色图片

- 每个槽位使用其自身的 `imageFilename`。
- 默认完整展示角色，使用等比 `contain`，不裁切身体。
- 支持现有 JPG、PNG、GIF 格式和 GIF 循环修正能力。
- 带 Alpha 通道的素材可呈现真正的透明桌宠效果。
- 不带 Alpha 通道的素材保留原图背景；程序不自动抠图。
- 本次讨论样图为 712×698 RGB PNG，不含 Alpha 通道，直接使用时会显示深色矩形背景。

### 8.2 信息层

默认状态只突出角色图片。鼠标悬停时显示：

- AI 名称和用户名。
- 内容摘要。
- 分页与必要操作控件。

信息以小气泡或轻量浮层呈现，不持续占用桌宠主体面积。

### 8.3 可访问性与动效

- 控件必须有中文无障碍名称。
- 桌宠根区域可获得键盘焦点并响应左右方向键；分页按钮仅在鼠标悬停时显示并
  进入 Tab 顺序，隐藏时同步设置 `aria-hidden`。
- 动效遵守 `prefers-reduced-motion`。
- 不添加持续干扰监控的循环 UI 动效；角色图片自身的 GIF 动画不受此限制。

## 9. 拖动、缩放与锁定

### 9.1 拖动

- 桌宠非控制区域可拖动原生窗口。
- 图片区域也属于可拖动区域。
- 分页按钮不得触发窗口拖动。
- 双击非控制区域返回主界面；单击或拖动不切换模式。

### 9.2 自由缩放

- 分页栏不显示缩放手柄。
- 缩放保持角色单元的宽高比例，禁止非等比拉伸角色图片。
- 普通滚轮用于翻页。
- `Ctrl + 滚轮`（Windows）或 `Command + 滚轮`（macOS）用于缩放。

尺寸滑块表示单格正方形边长，所有布局统一最小 32px。窗口宽高由单格边长分别
乘以列数、行数生成；底部分页条悬浮在画布上，不额外增加窗口高度：

| 布局 | 最小窗口 | 单格尺寸 |
| --- | --- | --- |
| 1×1 | 32×32 像素 | 32×32 像素 |
| 1×2 | 64×32 像素 | 32×32 像素 |
| 2×1 | 32×64 像素 | 32×32 像素 |
| 1×3 | 96×32 像素 | 32×32 像素 |
| 3×1 | 32×96 像素 | 32×32 像素 |
| 2×2 | 64×64 像素 | 32×32 像素 |

具体边界按逻辑像素定义，并在不同 DPI 显示器上转换为当前物理尺寸。单格最大
边长为当前显示器工作区逻辑最短边的 1/4，再除以布局最长轴格子数，因此所有
布局的窗口长边上限统一为屏幕最短边的 1/4。窗口跨显示器后重新计算上限，
超限时自动缩小；极小工作区上统一的 32px 单格最小值优先。

### 9.3 尺寸滑块

独立桌宠设置窗口提供连续尺寸滑块，显示当前单格的逻辑像素边长。
自由缩放后的尺寸作为当前布局的自定义历史尺寸保存。

### 9.4 独立布局几何

六种布局分别记忆完整窗口几何，而不只记忆一个共享尺寸：

```text
singleGeometry
rowGeometry
columnGeometry
row3Geometry
column3Geometry
gridGeometry
```

首次进入桌宠且没有可用几何时，使用默认 64px 单格边长（再按当前显示器范围
收敛），并放在主显示器工作区右下角。
运行中切换布局时保持当前窗口左上角锚点，并将当前画布尺寸收敛到新布局范围；
只有越过工作区右侧或下侧时才向内调整。分别保存的几何用于重启与模式恢复，
切换布局本身不会把窗口跳回另一布局曾经保存的位置。

### 9.5 锁定

- 锁定后禁止拖动和缩放。
- 锁定不影响翻页、悬停信息或返回主界面。
- 托盘和独立桌宠设置窗口都可解除锁定。
- 首版不提供鼠标穿透，避免窗口进入无法直接操作的状态。

## 10. 持久化设计

### 10.1 实际结构

以下是 `Preferences.windows` 的实际结构示例；尺寸为物理像素，示例中 2×2 布局的
`petSize = 64` 是单格逻辑边长，因此在 `scaleFactor = 2` 时窗口为 256×256 物理像素：

```json
{
  "windows": {
    "activeMode": "pet",
    "mainWindow": {
      "normalGeometry": {
        "x": 120,
        "y": 80,
        "width": 1280,
        "height": 800,
        "scaleFactor": 2
      },
      "maximized": true
    },
    "petWindow": {
      "layout": "grid",
      "focusedSlot": 0,
      "singleGeometry": null,
      "rowGeometry": null,
      "columnGeometry": null,
      "row3Geometry": null,
      "column3Geometry": null,
      "gridGeometry": {
        "x": 1400,
        "y": 500,
        "width": 256,
        "height": 256,
        "scaleFactor": 2
      },
      "petSize": 64,
      "alwaysOnTop": true,
      "locked": false
    }
  }
}
```

窗口几何记录保存时的物理坐标与物理宽高，同时记录 `scaleFactor`；恢复时按“保存宽高 ÷ 原缩放因子 × 当前缩放因子”换算，从而保持用户感知到的逻辑尺寸。旧配置没有 `scaleFactor` 时按原始物理像素兼容读取。

### 10.2 保存时机

- 模式切换成功后立即保存。
- 布局、关注槽位、画布尺寸、置顶和锁定发生变化后立即保存。
- 移动和自由缩放使用约 300～500ms 防抖后保存。
- 隐藏、关闭请求和正常退出前执行一次最终保存。
- 配置写入使用临时文件加替换，避免进程中断留下半截 JSON。

### 10.3 旧配置迁移

现有 `window` 字段迁移为：

```text
mainWindow.normalGeometry
```

旧配置缺少桌宠字段时使用以下默认值：

```text
activeMode = main
petWindow.layout = grid
petWindow.focusedSlot = 0
petWindow.petSize = 64
petWindow.alwaysOnTop = true
petWindow.locked = false
```

`petSize = 64` 表示默认单格边长；窗口显示时会按当前布局和显示器动态收敛，
所有布局的有效最小单格边长均为 32px。2.0.0 之前的 `scalePreset`
不再参与尺寸计算，旧几何仍用于恢复位置，新的有效画布尺寸会在下一次窗口事件后保存。

迁移不得重置设备 ID、设备名、监控行列、图片显示模式或开机自启状态。

## 11. 多显示器与异常恢复

- 恢复前检查窗口与当前显示器工作区是否有效重叠。
- 对桌宠不能只保证露出 64×64 区域；应将整个窗口收敛进可用工作区，至少确保可拖动区域和右键操作可达。
- 原显示器已断开时，将窗口放到当前主显示器工作区右下角。
- DPI 或缩放比例变化时保持逻辑尺寸，不沿用错误的物理像素大小。
- 恢复后的尺寸超出工作区时，按比例缩小到允许范围。
- 布局切换导致窗口越界时，向工作区内部调整位置。
- 打开桌宠设置窗口时，以桌宠当前所在显示器的工作区居中；桌宠跨屏后再次打开，
  设置窗口必须跟随到新的显示器。
- 偏好文件损坏时回退到 `main` 模式；主窗口按无历史数据的现有规则最大化。

## 12. 命令与状态边界

Rust 侧通过以下命令统一管理窗口模式与桌宠状态：

- `get_window_state`
- `switch_app_mode`
- `hide_current_window`
- `show_pet_settings` / `hide_pet_settings`
- `set_pet_layout` / `set_pet_focused_slot`
- `set_pet_size` / `resize_pet_by`
- `set_pet_always_on_top` / `set_pet_locked`
- `start_pet_drag`

窗口互斥、恢复、失败回滚和偏好落盘应由 Rust 侧执行，避免两个前端窗口分别操作后产生竞态。

`MonitorState` 仍是监控业务状态。窗口模式偏好可以作为单独的窗口状态返回，避免把纯 UI 几何混入局域网设备状态。

## 13. 首版范围外

以下能力明确不属于首版：

- 主窗口与桌宠同时显示。
- 3×3 以上的桌宠单页布局。
- 根据窗口尺寸自动切换 1×1/2×2。
- 首次有图定位完成后，继续因新数据到来而自动翻页。
- 用户固定或重排“收藏槽位”。
- 鼠标穿透及全局快捷键解除穿透。
- 自动抠图或移除传入图片背景。
- 根据角色轮廓创建不规则原生窗口点击区域。

## 14. 验收标准

### 14.1 模式与启动

- 任意时刻桌面上只显示主窗口或桌宠窗口之一。
- 切换模式后重启应用，恢复切换后的模式。
- 开机自启进入桌宠模式时不闪现主窗口。
- 看板隐藏到托盘后可通过“显示看板”恢复，且仍处于看板模式。
- 桌宠隐藏到托盘后可通过“看板模式”回到看板，再按需重新进入桌宠模式。
- 目标窗口显示失败时能够回到来源窗口。

### 14.2 布局与分页

- 默认桌宠布局为 2×2。
- 1×1 每页显示一个槽位，1×2/2×1 每页最多显示两个槽位，1×3/3×1 每页最多显示三个槽位，2×2 每页最多显示四个槽位。
- 首尾分页正确循环。
- 最后一页不足当前布局容量时保留对应空位。
- 布局切换后保持当前关注槽位。
- 监控行列减少时不会访问越界槽位。
- 当前页没有图片时，窗口挂载后首次收到有效图片会定位到首个有图槽位所在页，
  后续更新不会继续抢占用户当前页。

### 14.3 窗口状态

- 主窗口和六种桌宠布局分别恢复自己的历史几何。
- 主窗口最大化状态可恢复。
- 桌宠置顶和锁定状态可恢复。
- 显示器断开、分辨率或 DPI 变化后窗口仍可见、可操作。
- 桌宠设置窗口每次在桌宠当前所在显示器居中；桌宠跨屏后不会仍弹到旧显示器。
- 连续移动或缩放不会为每个像素变化同步写盘。

### 14.4 操作

- 双击桌宠非控制区域返回主界面。
- 普通滚轮翻页，组合键滚轮缩放。
- 锁定后无法拖动或缩放，但仍可翻页和返回主界面。
- 独立桌宠设置窗口可切换看板、隐藏桌宠及解除锁定；托盘可按当前模式切换
  看板/桌宠并解除桌宠锁定。
- JPG/PNG/GIF 均正常显示；带透明通道的素材保持透明效果。
- 看板模式托盘按顺序仅显示“桌宠模式、显示看板、开机自启、退出”。
- 桌宠模式托盘按顺序仅显示“看板模式、锁定桌宠、开机自启、退出”。
